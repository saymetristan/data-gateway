# Tools y Consultas Directas

El Data Gateway proporciona dos formas distintas de acceder a tus datos integrados, cada una enfocada a una audiencia distinta.

## 1. Integración vía Protocolo MCP (Tools)

Ésta es la interfaz recomendada si vas a usar un Agente de IA, asistentes conversacionales, Whaapy, o editores inteligentes como Cursor y Claude Desktop.

- **Cómo funciona:** El Gateway compila los esquemas de mapeo de las fuentes que estén en estado `agent_ready` y crea herramientas (`tools`) que los agentes entienden.
- **Herramientas generadas:**
  - `search_<entidad>`: Búsqueda híbrida. Recibe `query` (texto libre), `limit`, filtros por campos `filterable`, y opcionalmente `prefer_<campo>` cuando el mapping marca `inferredBehavior: "prefer"`.
  - `check_availability_<entidad>`: Recupera un registro exacto si el agente ya conoce su identificador.
- **Formato:** Sigue la especificación del Model Context Protocol. El agente recibe un esquema JSON y sabe qué variables puede mandar.
- **Ventaja:** Cero configuración en el agente. Le conectas el servidor MCP y el agente descubre las bases de datos al vuelo.

Detalle de filtros vs preferencias: [Ranking y Preferencias](/concepts/ranking-and-preferences).

## 2. API REST Directa (`POST /query`)

Si estás desarrollando una aplicación de software, un panel interno o un portal que no usa agentes (o donde controlas el flujo), puedes saltarte la capa MCP.

```bash
curl -X POST "https://data.whaapy.com/query" \
  -H "Authorization: Bearer $WORKSPACE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "tela antimancha",
    "limit": 10,
    "sourceId": "{source_id}",
    "filters": [
      { "field": "available", "op": "eq", "value": true }
    ],
    "preferences": [
      { "field": "collections", "op": "contains", "value": "Verano", "boost": 0.3 }
    ]
  }'
```

### Parámetros

| Campo | Descripción |
| --- | --- |
| `query` | Texto libre. También alimenta la extracción NL según el mapping. |
| `limit` | Máximo de resultados (default 10, max 50). |
| `entity` / `sourceId` | Acota entidad o fuente. |
| `filters` | Restricciones **duras**. Legacy `{ "campo": "valor" }` o array tipado `{ field, op, value }`. Ops: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `in`, `contains`, `containsAny`, `containsAll`. |
| `preferences` | Boosts **blandos** post-RRF. Misma forma tipada + `boost` opcional. No excluyen. |
| `useLlmFallback` | Opcional; extracción NL asistida por LLM sobre texto residual. |

### Respuesta

- `results` — id, entity, score, data (sin campos sensibles)
- `applied_filters` / `applied_preferences`
- `query_type` — `filter_only` \| `lexical` \| `hybrid_search`
- `confidence` — score determinístico (sin LLM)
- `sources_used`, `warnings`

## ¿Cuándo usar cada una?

- **Tools (MCP)** cuando hables con un LLM o un framework de agentes MCP.
- **API directa** cuando escribes código convencional o tu propio orquestador y solo quieres el motor de retrieval.
